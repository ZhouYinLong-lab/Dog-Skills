# Rapid Domain Learning

把一个宽泛的学习愿望，转化成一条可执行、可复盘的研究型学习路径。默认采用“范围确认 → 领域地图 → 直觉优先阅读 → 知识结构 → 细节循环”的顺序。

## 总体规则

- 先收敛学习目标，再检索资料；不要直接对模糊主题列论文。
- 在开始找资料前，向用户展示一份简短的“学习契约”，并等待确认或修改。
- 不把“快速”理解为跳过理解；优先建立主线和因果关系，再深入技术细节。
- 优先使用一手论文、官方文档、教材、综述和可靠数据库，并为关键判断保留来源。
- 将“开山论文”理解为开端论文、范式转折论文或多个源头节点，允许一个领域有多个起点。
- 论文数量是启发式：通常选择 3—7 篇核心论文和 10—30 篇外围论文，根据领域成熟度、用户基础和时间预算调整。
- 不把“达到原作者高度”作为一次任务的完成标准；以能解释主线、定位新论文和提出后续问题作为阶段性完成标准。

## 工作流

### 1. 收敛学习目标

先只从用户输入中提取最小必要信息，不把完整计划当成开始学习的门槛：

```text
学习主题：
具体问题或应用场景：
希望掌握的方面：历史主线 / 核心概念 / 方法实现 / 研究前沿 / 实践应用
不包含的范围：
```

已有基础、时间预算、目标深度和最终产物只在用户主动提出，或后续确实需要制定计划时再询问。若主题仍然宽泛，优先询问“想解决什么问题”和“最想理解哪一部分”，不要连续追问无关偏好。将整理结果展示给用户，用一句话请求确认：

> 我理解你想先从【主题 / 问题】入手，重点看【范围】。我会先画一张地图，再带你进入核心论文。这样理解对吗？

用户确认后再进入下一步。若用户修改范围，更新学习契约，不保留旧假设。

### 2. 建立领域地图

围绕确认后的范围完成以下工作：

1. 找到领域的起点节点、关键转折和当前主流路线。
2. 选择核心论文，并说明每篇论文解决的具体问题。
3. 为核心论文补充外围论文、综述或教材章节。
4. 建立“问题 → 方法 → 局限 → 后续回应”的时间线或关系图。
5. 标注资料可信度、争议点、前置知识和推荐阅读顺序。

第一遍只输出一张可导航的地图，不要求用户立刻读完全部论文。详细模板见 [references/paper-landscape.md](references/paper-landscape.md)。

### 3. 第一遍提炼核心直觉

对核心论文逐篇制作“直觉卡片”，优先回答：

- 作者看到了什么问题？
- 之前的方法为什么不够？
- 作者最初的简单而深刻的想法是什么？
- 这个想法如何被转化为方法、实验或证明？
- 这篇论文留下了什么限制，后续工作如何回应？

第一遍阅读不要求完整推导所有数学。只在某个技术细节阻断主线时解释它，并明确哪些细节可以延后。详细模板见 [references/intuition-first-reading.md](references/intuition-first-reading.md)。

### 4. 搭建知识结构并循环补细节

将核心论文作为知识结构中的固定节点，把其他论文挂到相应的问题、方法或局限上。输出：

- 时间线：研究如何演进；
- 问题树：每篇工作要解决什么；
- 方法树：方法之间继承、替代或冲突的关系；
- 局限链：旧问题如何产生新问题；
- 细节队列：下一轮应该补哪些公式、证明、实现或实验。

随后反复执行：

```text
回看整体地图 → 选择一个细节 → 补足前置知识 → 更新论文卡片 → 修正整体理解
```

不要把一次循环做成无限钻研。每轮都给出“已经理解”“仍然模糊”“下一步验证”三栏。详细规则见 [references/knowledge-synthesis-loop.md](references/knowledge-synthesis-loop.md)。

## 默认交付物

使用 [references/output-templates.md](references/output-templates.md) 的结构，至少交付：

1. 已确认的学习契约；
2. 核心论文地图与阅读顺序；
3. 核心论文直觉卡片；
4. 领域知识结构与演进关系；
5. 当前理解、待补细节和下一步问题。

如果用户要求“7 天计划”，把 7 天作为时间预算重新分配任务，不要假装所有领域都能在 7 天内精通。若用户要求可视化展示，参考 `assets/demo.html` 的信息层级和视觉语言，输出或改造 HTML，而不是把研究结果塞成一长段文字。

## AI 的使用边界

- 可以用 AI 解释局部概念、比较方法、定位前置知识和检查用户自己的理解。
- 不要把整批论文交给 AI 后只返回摘要；摘要不能替代领域直觉和结构化记忆。
- 对不确定的论文归因、历史顺序和技术结论，标注不确定性并优先核对一手来源。
- 让用户定期用自己的话复述核心直觉，必要时通过反问、对比和小测验检验理解。
